# 별도 수정 TB 재검증

## 연구 질문
원본 제출 RTL을 유지한 상태에서 TB의 입력 범위·초기화·종료 조건을 정정하면 X 없는 유효 출력 1,000개를 얻고 기존 순차 입력 결과를 재현하는가?

## 실험 방법
기준 커밋은 exp-hyunseo의 99f7f72이다. vivado/submit/PPA_AdaPath_NPU_A.zip을 별도 작업 폴더에 풀고 동일한 src/*.v, 헤더, 데이터 파일을 사용하였다. 원본 sim/top_tb.v는 수정하거나 컴파일 대상으로 대체 저장하지 않았다. 새 파일 top_tb_1000_corrected.v는 원본 top_tb_1000의 포트·가중치 로딩·배선 및 posedge의 nonblocking 픽셀 전달 방식을 유지하고, 구동·집계 부분을 별도 구현하였다. 컴파일에는 원본 TB 대신 이 새 모듈을 명시적으로 선택하였다.

다음 조건을 정정하였다.

- 초기 상태, 데이터, 클럭, 리셋, 카운터를 명시적으로 초기화하고 리셋을 실제 상승 클럭에서 관측하도록 하였다.
- 난수 추출을 $urandom_range(999,0)으로 제한하였다. 고정 seed 2026을 $urandom으로 설정한 뒤 해당 Icarus 난수열을 사용하였다.
- img_idx<784일 때만 배열을 읽었다. 이후에는 0을 구동하여 785번째 픽셀 및 마지막 이미지 다음 주소의 불필요한 읽기를 없앴다.
- 출력에서 정답 및 출력 수를 집계하고, 1,000번째 출력까지 반영한 후 종료하였다. 이미지마다 784회 읽기와 4,000 cycle 제한을 검사하였다.
- 별도 corrected_observer.v가 클럭마다 입력 읽기 범위와 X, 유효 출력 수와 X decision을 독립 집계하였다. X 검사의 범위는 읽은 픽셀과 valid_out에서의 decision이며 내부 RTL의 모든 노드를 검사한 것은 아니다.

순차 0~999 입력과 복원 무작위 입력을 각각 1,000회 실행하였다. 두 실행은 같은 입력 파일과 가중치를 사용하였다. 보호 대상의 실행 전후 SHA-256은 validation.json에 보존하였으며 모두 같았다. 파일 집합은 원본 ZIP, 추출 원본 TB, 모든 src 파일 및 data 파일이다.

## 결과

| 항목 | 순차 입력 | 무작위 입력 seed 2026 |
|---|---:|---:|
| 유효 출력 | 1,000 | 1,000 |
| 정답 | 970 (97.0%) | 971 (97.1%) |
| Easy / Medium / Hard | 960 / 0 / 40 | 956 / 0 / 44 |
| 범위 밖 읽기 | 0 | 0 |
| X 픽셀 읽기 / X 유효 출력 | 0 / 0 | 0 / 0 |
| 픽셀 읽기 | 784,000 | 784,000 |
| 타임아웃 | 0 | 0 |
| 서로 다른 이미지 인덱스 | 1,000 | 639 |
| TB 인터페이스 평균 cycle | 853.840 | 854.524 |

순차 입력 결과는 기존의 정답 970 및 모드 분포 960/0/40을 재현하였다. 무작위 입력 1,000개 모두 같은 인덱스의 순차 판정·모드와 일치하였다. 무작위 입력의 1개 높은 정답 수는 추출 표본의 차이를 포함한 결과이며 설계 개선이나 유의한 정확도 향상으로 해석하지 않았다. 무작위 639개는 고유 인덱스 수이지 고유 이미지 내용 수가 아니다. 원본 입력은 고유 100장의 반복이므로 독립 1,000장 평가가 아니다.

TB 인터페이스 cycle은 rst_n이 해제된 첫 상승 에지부터 valid_out을 관측한 상승 에지까지 양 끝을 포함한 카운터이다. Easy=847, Hard=1018이며, 기존 실험의 코어 cycle Easy=845, Hard=1016과 집계 경계가 2 cycle 다르다. 새 순차 평균 853.84를 기존 851.84와 같은 정의의 지연으로 대체하지 않았다. 원본과 같은 10 ps 기능 시뮬레이션 클럭을 유지했으며 물리 주파수·지연 측정이 아니다.

## 결론과 한계
수정 검증 환경에서는 관측된 입력 범위·X·출력 수 문제가 해소되었다. 원본 TB 자체는 변경되지 않았으므로 원본 TB의 문제가 해결되었다고 주장하지 않는다. 이 실행은 Icarus 검증이며 Vivado 과거 실행을 재현한 것이 아니고 공식 제출 TB의 대체 승인도 아니다. 원본 TB 문제는 별도 진단 로그와 함께 구분하여 보고한다. 원본 RTL에는 변경이 없다.

## 재현
저장소 루트에서 아래와 같이 실행한다. --scratch는 별도 작업 디렉터리이며 기존 결과가 없는 경로를 권장한다. Python 표준 라이브러리와 Icarus Verilog가 필요하다.

```powershell
python results_hs/corrected_tb/run_validation.py --iverilog C:/iverilog/bin/iverilog.exe --vvp C:/iverilog/bin/vvp.exe --scratch work/corrected_tb_replay
```

compile.log, sequential.log, random_seed2026.log에 원시 실행을 보존하였다. CSV의 각 행은 출력 번호, 이미지 인덱스, 라벨, 판정, 모드, 인터페이스 cycle이다. runner는 두 관찰 결과와 순차 전체 인덱스, 무작위 대 순차 판정·모드 일치를 검증하고 실패 시 종료한다. validation.json에는 실행 명령과 컴파일러 버전 및 원본 파일 해시가 있다. 빈 compile.log는 컴파일 오류가 없었음을 뜻한다.
