# 클럭 게이팅 전력 표본 확대 — 완료 결과 및 사전 고정 계획

현재 상태: 18개 신규 구간 계산과 검산을 완료하였다. 기존 Hard 4개 결과를 포함한 고유 입력 40개 확장 결과 및 보고서 반영본은 exp-hyunseo-final에 업로드하였다. main 병합은 서현이 담당한다. 원본 RTL은 수정하지 않았다. 아래 표본 선정, 통제 및 실행 절은 실행 전 고정한 계획을 보존한 기록이다.

## 표본 선정

입력 파일의 100개 고유 픽셀 배열을 기준으로 Easy 96개 중 36개를 seed=20261030으로 단순 무작위 비복원 추출하였다. Hard는 고유 표본 4개 전부를 포함한다. 총 40개 고유 입력이며, 1,000개 독립 표본을 의미하지 않는다. [사전 고정 목록·해시](sampling_plan.json).

Easy 36장은 4장씩 9개 구간으로 나누고 같은 순서로 두 설계를 실행한다. Hard 4장은 이전 커밋 1a6d910의 검증된 동일 넷리스트·동일 조건 전력 결과를 재사용한다. 이를 새로 얻은 독립 반복 측정으로 세지 않는다. 따라서 신규 실행은 18개 구간·72회 추론이며, 기존 Hard 8회와 합쳐 분석 대상은 40개 입력×2개 설계이다. 이전 소표본과 일부 입력이 겹칠 수 있으며, 새 분석 안에서는 각 고유 입력을 한 번만 반영한다.

## 통제 및 집계

기존 전용 ICG/버퍼 포함 넷리스트·ODB·셀 모델·TB·입력·가중치·ASAP7 RVT TT·100 MHz·reset/start 포함 창을 유지한다. 합성 재실행 및 설계 변경은 하지 않는다. 실행 전 파일 해시를 검증하고 각 입력의 decision·mode·margin·cycle이 전체 RTL 로그와 일치하지 않으면 중단한다. VCD 주석 누락과 타이밍 위반도 검사한다.

각 구간 에너지는 평균 전력(W)×VCD 관측 시간(s)÷4로 계산한다. Easy 에너지는 동일 크기 9개 구간의 평균, Hard는 기존 4장 구간 값으로 제시한다. 전체 파일의 96:4 경로 비율을 사용하는 경우 0.96×Easy 평균 에너지+0.04×Hard 평균 에너지로 산출한 **해당 파일에 한정된 층화 추정치**라고 표시한다. 표본의 36:4 비율로 단순 평균한 값을 전체 파일 평균으로 사용하지 않는다. 경로별 cycle 차이가 있으므로 평균 전력은 에너지를 해당 가중 관측 시간으로 나누어 계산하며 전력에 96:4를 직접 적용하지 않는다.

9개 Easy 구간 사이의 범위·표준편차는 표본 구성에 따른 산포이며 독립 반복 실행의 측정 오차나 이미지 단위 신뢰구간이 아니다. 글리치·배선 RC·실제 CTS·다중 PVT를 제외한 배치 전 추정이라는 기존 한계는 유지된다. 더 넓은 데이터셋의 일반화나 실리콘 실측을 주장하지 않는다.

## 실행

Ubuntu-24.04 `/root/ppa-clockgate-expansion40`에 독립 실행 디렉터리를 준비하였다. `run_expansion.py --stage /root/ppa-clockgate-expansion40 --prepare-only`로 계획을 고정한 뒤, 같은 명령에서 `--prepare-only`를 빼면 실행한다. 기존 결과 덮어쓰기나 묵시적 재시작은 거부한다. 실행 로그는 runner.log, 구간별 로그·JSON과 runs.json에 보관한다. 대용량 VCD는 로컬 보관하며 최종 결과에 해시를 제공한다.

확정 수치는 아래 완료 결과에 제시하였으며, 전달용 문단과 캡션은 HANDOFF.md에 보존하였다.

## 완료 결과 (2026-10-30)
18개 신규 구간 계산 및 72개 출력의 기준 RTL 일치 검증을 완료하였다. Easy 36개 평균 에너지 감소율은 **25.8629%**, 기존 Hard 4개 결과는 **20.7426%**, 파일 모드 구성비 96:4 가중 에너지 추정 감소율은 **25.5934%**이다. 모두 합성 후 활동도 기반 추정이며 물리 실측이 아니다.

[서현에게 넘길 보고서 문단·권장 위치·표·캡션](HANDOFF.md), [반올림 전 수치 및 검산](power_results/summary.json), [원시 로그](power_results/logs/), [검산·수집 코드](package_expansion.py)를 참조한다. 기존 사전 계획은 위에 보존하였다. 실험 당시 원본 RTL과 보고서는 수정하지 않았으며, 이후 승인된 보고서 반영 작업에서 3.7절과 4.2절을 갱신하였다. 보고서 반영 확인은 report_integration_validation.json을 참조한다.
