# 클럭 게이팅 전후 전력 재측정 프로토콜

이 문서는 실행 조건이다. 최종 전력 결과나 타이밍 통과를 의미하지 않는다.

## 비교 설계 및 통제 조건

- 지정주제 A: C1=3, C2=3, C2_MED=1, 클래스 10, 기존 A 가중치와 임계값.
- 기준 설계와 게이팅 설계 모두 같은 저장소 RTL에서 생성한다. 게이팅 설계만 별도 `adapath_top_cg`와 `icg_latch`를 사용한다. ASIC 합성용 `icg_asap7.v`는 `ICGx1_ASAP7_75t_R`를 명시적으로 인스턴스화한다. 이전 RTL 체크포인트의 기술 독립적 latch/AND 모델과 구분한다.
- 합성 top의 가중치는 입력 포트이며, 시뮬레이션 TB에서 A 가중치를 구동한다. 상수 가중치 제출용 chip의 합성 결과와 구분한다.
- ASAP7 RVT, TT 라이브러리를 두 설계의 합성과 전력 분석에 동일 적용한다. 과거 팀 합성 환경의 설정과 무조건 같다고 가정하지 않는다.
- 합성 목표 주기 1,000 ps, 입출력 지연은 주기의 20%. 전력 분석은 100 MHz(10 ns)에서 실행한다. 합성 목표 주파수와 동작 가능 최대 주파수는 다르다.
- `ABC_AREA=1`, `SYNTH_HIERARCHICAL=0`, `SYNTH_MEMORY_MAX_BITS=65536`, `ADDER_MAP_FILE` 공백. 자동 클럭 게이팅 `INFER_CLKGATES=0`.

## 입력 및 측정 창

기존 전력 TB `glsim/tb_gl_A.v`를 별도 디렉터리로 복사해 사용한다. 원본 파일은 수정하지 않는다. 입력 인덱스는 0부터 센다.

| 런 | 입력 인덱스 | RTL에서 확인한 경로 | 각 입력의 cycle |
|---|---|---|---|
| Easy | 1, 2, 3, 4 | Easy 4장 | 845, 845, 845, 845 |
| 혼합 | 5, 6, 7, 8 | Hard 1장 + Easy 3장 | 1016, 845, 845, 845 |
| 순수 Hard | 5, 37, 51, 62 | Hard 4장 | 1016, 1016, 1016, 1016 |

게이팅 전후 RTL에서 기존 두 구간의 decision, mode, margin, cycle 로그가 일치하였다. 전체 1,000회 순차 입력에서도 전용 ICG 변형과 기준 설계의 출력·cycle 불일치는 0건이었다. Easy 런의 마지막 TB 시간은 34.316 us, 혼합 런은 36.026 us, 순수 Hard 런은 41.156 us이다. 게이트 수준의 실제 VCD 시작·끝 시간은 별도로 읽어 확인한다. 순수 Hard 표본은 전체 순차 로그에서 먼저 나타난 네 Hard 입력을 고정한 것이며 대표성이나 무작위 표본성을 주장하지 않는다. 인덱스 51, 62의 오분류는 기준 RTL에도 존재한다.

입력 바이트 대조 결과, 이번 `input_1000.txt`의 1,000개 프레임은 100개의 서로 다른 픽셀 배열이 각각 10회 반복된 구성이었다. 따라서 970/1,000은 1,000회 실행에 대한 정확한 채점 결과이지만, 독립적인 1,000개 이미지의 일반화 검증으로 해석하지 않는다. 이 감사는 해당 파일에 한정되며 다른 데이터셋에 대한 추론이 아니다.

전체 VCD 덤프 창에는 이미지별 reset(12 clocks)과 start가 포함된다. 동일한 창의 평균 전력 × 창 길이 / 처리 이미지 수로 이미지당 런 평균 에너지를 계산한다. 혼합 런의 값을 순수 Hard 에너지로 표현하지 않는다. 세 구간은 12회 실행·11개 고유 입력(인덱스 5 중복)으로, 그 결과를 1,000회 전체 평균이나 일반적인 모든 입력의 감소율로 표현하지 않는다.

## 기능·측정 검증

1. 합성 결과에 미매핑 내부 셀이나 라이브러리 정의가 없는 blackbox가 없는지 확인한다. 전용 ICG가 실제 넷리스트에 남아 있는지 확인하고 셀 면적을 보존한다.
2. 표의 세 구간(각 4회, 합계 12회·11개 고유 입력)을 각각 두 설계의 게이트 수준에서 실행하여 RTL 로그와 decision·mode·margin·cycle을 대조한다. 타임아웃, X 출력, 불일치가 있으면 해당 결과를 유효한 전력 비교로 사용하지 않는다.
3. Icarus용 표준셀 모델은 원본의 `specify` 구간을 제거하고 `delayed_*` 핀을 해당 입력에 연결한 별도 복사본이다. Icarus의 timing-check 지연 핀 미지원에 대응한 **무지연 기능 시뮬레이션**이며 SDF 타이밍 검증이 아니다. 전력/STA용 Liberty 파일은 수정하지 않는다.
4. 원시 VCD와 넷리스트·ODB·입력·가중치·라이브러리 해시, 도구 버전 및 명령을 보관한다. GitHub에는 용량을 고려해 로그와 요약·해시·재현 스크립트를 우선 제공하고, 대용량 VCD의 보관 위치를 명시한다.
5. VCD의 pin activity 적용률과 미주석 신호 영향을 확인한다. gated clock의 실제 활동 감소를 점검하며 RTL edge 수만으로 전력 감소를 계산하지 않는다.
6. 생성 클럭, unconstrained path, clock-gating setup/hold, max slew/capacitance/fanout 위반을 기록한다. 최종 비교에서는 두 설계 모두 propagated clock을 적용한다. 배치·배선·다중 PVT 영향은 한계로 명시한다.

## 클럭 부하와 버퍼 모델

합성 직후 단일 ICG가 후단 FF 4,105개를 직접 구동하는 구조에서 부하·slew 및 setup 위반을 관찰하였다. 이 구조의 전력 값을 최종 결과로 채택하지 않는다. `buffer_clocks.tcl`로 합성 ODB의 복사본에 동일한 BUFx2 셀과 최대 분기 수 4의 결정론적 버퍼 트리를 구성한다. 핀 이름을 정렬하여 4개씩 묶는 과정을 재귀적으로 적용한다. 게이팅 설계의 ICG 입력은 root clock에 연결하고, ICG 출력 뒤의 후단 트리와 전단부 트리를 별도로 구성한다. 전단 트리 뒤에 ICG와 후단 트리를 직렬로 연결했던 중간 진단 구조는 hold 위반 때문에 제외하였다.

이 처리는 셀 입력 부하와 클럭 버퍼의 전력·지연을 포함하는 **배치 전 논리적 부하 모델**이다. 실제 배치 좌표, 배선 RC, 물리적 CTS 및 skew 최적화를 재현하지 않는다. 최종 버퍼 넷리스트로 기능 VCD를 다시 생성하고, 같은 ODB에 라이브러리 기반 propagated-clock STA와 VCD 전력 계산을 적용한다. 무지연 VCD이므로 셀·배선 지연에 의한 글리치 전력은 모델링하지 않는다. 이 조건에서의 STA 통과를 실장 또는 실리콘의 타이밍 보증으로 확대 해석하지 않는다.

## 해석 범위

본 실험은 합성 넷리스트의 VCD에 기반한 pre-layout 전력 추정이다. 실리콘에서 측정한 전력이 아니다. 새 결과를 기존 28.7% 상한 추정이나 Reference 대비 개선율과 직접 등치하지 않는다. Reference를 같은 조건에서 재실행하지 않았다면 Reference 대비 새 개선율을 주장하지 않는다.
