# 최종 보고서의 표본 수 및 검증 범위 교정

기준은 main `6cf837b4d21ee530348caa53578b77d9a8b786d3`이다. 기존 결과를 폐기하거나 새 실험을 수행한 것이 아니라, 보존된 결과의 표본 단위와 검증 조건을 정확히 표현하였다. 게시 브랜치는 `exp-hyunseo-final`이며, main 반영은 최종 편집자가 담당한다.

## 확인 결과

| 구분 | 확인값 | 해석 |
|---|---:|---|
| 넷리스트 채점 출력 | 250회 | 기본 시드 및 seed 2~5의 부분 실행 합계 |
| 서로 다른 입력 인덱스 | 228개 | 파일 안의 주소 기준 |
| 서로 다른 픽셀 내용 | 95종 | 784개 픽셀을 바이트로 정규화한 뒤 SHA-256 비교 |
| 판정 및 처리 cycle 일치 | 각각 250/250 | 기존 순차 RTL CSV의 동일 인덱스와 대조 |
| 정답 수 | 237/250 | 판정 일치율과 분류 정확도를 구분 |
| 인덱스 범위 | 모두 0~999 | 이 부분 실행에는 인덱스 1000 사례 없음 |
| 넷리스트 1,000회 전체 완료 | 확인되지 않음 | 기본 시드는 110회, 다른 시드는 70/66/2/2회 |

원본 입력 파일은 1,000개 위치에 고유 픽셀 내용 100종을 포함한다. 현재 관측된 228개 위치에서는 고유 내용 95종을 확인하였다. 반복 관측을 독립 이미지 표본으로 해석하지 않는다. xfill은 TB data_in의 어느 비트든 X 또는 Z가 있으면 DUT 입력 바이트 전체를 0으로 치환한다. 원본 TB 소스를 수정하지 않았다는 사실과 DUT가 받는 입력을 치환했다는 사실을 구분하였다.

## 재현 및 근거

저장소 루트에서 실행한다. Python 표준 라이브러리만 사용한다.

```sh
python results_hs/report_scope_correction/audit_scope.py
```

- `scope_audit.json`: 입력 및 로그 해시, 실행별 출력 수, 고유 인덱스 수, 고유 픽셀 내용 수와 판정/cycle 대조 결과.
- `observations.csv`: 250개 출력 각각의 인덱스, 픽셀 내용 해시, 판정 및 처리 cycle과 RTL 대조값.
- `document_qa.json`: 문서 쪽수, 표 및 그림 보존 검사, 보호 경로 미변경 확인, 최종 문서 해시.
- 입력은 커밋된 `vivado/submit/PPA_AdaPath_NPU_A.zip` 안의 `data/input_1000.txt`를 사용하였다.
- 로그는 `evidence/vivado_netlist/logs/net_seed*.log`, RTL 기준은 `results_hs/corrected_tb/sequential.csv`를 사용하였다.
- cycle 대조는 기존 로그의 10 ps 클럭, OBS 기록이 valid보다 한 클럭 늦다는 조건, 최초 비채점 valid 시각 10175 ps 및 회차 간 리셋 1 cycle을 반영하였다. 이는 물리 주파수 검증이 아니다.

보고서는 `report/make_final_report.py`로 DOCX를 생성하고 `report/export_pdf.ps1`로 Microsoft Word 16.0의 목차 및 필드를 갱신한 뒤 PDF로 내보냈다. 43쪽 전체 배치와 수정 페이지를 확인하였다. 미처리 참조, `%%`, 가운데점은 없었고 그림/표 번호는 각각 1~26, 1~34로 연속이다.

## 최종 편집자 인수인계

1. 최신 main 및 본 교정 커밋의 차이를 확인한다. 서현의 미커밋 편집 또는 이후 변경이 있으면 보고서 파일을 통째로 덮어쓰지 말고 위 교정 문단을 현재 편집본에 반영한다.
2. 보고서 생성 원문만 가져오는 경우에도 `results_hs/report_scope_correction/scope_audit.json`을 함께 가져온다. 생성기가 이 파일을 읽어 95종 및 기존 요약과의 정합성을 확인한다.
3. 병합 후 DOCX/PDF의 위 위치와 목차를 확인한다. 새 실험 또는 원본 RTL/TB 변경은 필요하지 않다. 넷리스트 전체 완료 기록이 별도로 생겼다면 해당 로그를 검증한 뒤에만 완료 범위를 갱신한다.
4. 최종 제출 안내에서 HWP 필요 여부, PDF 허용 여부, 파일명, 설계 자료 동봉 방법 및 마감 시각을 확인한다. 확인되지 않은 항목을 충족했다고 단정하지 않는다.
5. 확인한 공개 제출 화면의 첨부파일 제한은 20MB이다. 현재 PDF는 약 3.31MB이나 최종 동봉 패키지 용량은 별도로 확인한다. 공개 2026 공지 및 양식에서 분량 제한을 발견하지 못했으며, 이를 무제한이라는 명시 규정으로 해석하지 않는다.
6. 자유주제의 실제 면적 및 타이밍 근거를 함께 제공하고, 전력은 대리 추정이라는 한계를 유지한다. 주최 측의 2026-08-07 안내는 소스, 도구/설정 및 적용 전후 Fmax/Power/Area와 측정 방법을 요구하므로 대리 추정의 인정 여부는 최종 제출 담당자가 확인해야 한다.

공식 2026 양식은 [본선 참가팀 안내](http://www.ccdc-knuidec.or.kr/html/dh_board/views/1851)의 첨부파일을 사용한다. 공개 [제출 화면](http://www.ccdc-knuidec.or.kr/html/dh_board/write/faq)의 일반 다운로드 링크와 연도를 구분한다. 공개 공지는 10월 31일을 기한으로 안내하지만, 별도 마감 시각과 최종 파일 형식은 팀이 수신한 최신 안내를 우선 확인한다.
